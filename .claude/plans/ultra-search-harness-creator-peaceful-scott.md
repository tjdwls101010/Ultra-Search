# Context

`ultra-search`는 판단이 필요한 조사와 주소를 아는 읽기를 구분하고, 실행 가능한 후속 명령과 간결한 로그를 제공한다는 점에서 harness-creator의 네 원칙에 잘 맞는다. 이번 개선은 기능 확대가 아니라, 도구가 소유해야 할 실행 계약을 CLI로 모으고 본문에는 판단 근거만 남기는 작업이다. 성진은 인터페이스 경계를 우선하고 CLI와 본문을 함께 개선하는 계획을 선택했으며, 코드·테스트만 보는 독립 검토 1개를 승인했다. 아직 구현은 승인하지 않았다.

## 네 프레임을 완료 기준으로 적용

단순한 버그 수정이 아니라 아래 네 기준을 모두 충족하는 것이 목표다. 문단 수나 글자 수 자체를 성공 지표로 삼지 않는다.

| 프레임 | 적용 | 완료 판정 |
|---|---|---|
| principle over rail | 목적·판단 근거·경계 사례를 남기고 무조건적인 명령 순서를 제거한다. | 모델이 알려진 URL, 출처 선택이 필요한 질문, 아직 미완료인 조사 등에서 이유를 바탕으로 경로를 고를 수 있다. 필수 실행 제약은 그 실패 이유가 설명되어 있다. |
| interface over document | 도구가 소유하는 입력·상태·커서·다음 행동·복구 방법은 CLI 도움말과 응답에 둔다. | 모델이 후속 명령을 재구성하거나 구현 소스를 열지 않고 최신 응답만으로 재감시·수거한다. 본문이 CLI 필드/기본값의 두 번째 규격서가 되지 않는다. |
| for user not developer | 읽는 이는 스킬을 사용하는 모델이다. 필요한 것은 지금 사용할 수 있는 역량·판단 근거·사용자에게 미칠 영향이다. | 내부 구현이나 개발 이력을 몰라도 결과·출처·비용·불완전성을 정확하게 전달한다. 유지보수 이유는 변경 기록에 남기고 런타임 본문으로 가져오지 않는다. |
| dense information | 의사결정에 기여하는 이유·예외·예시만 유지하고 중복·자기변호·발견 과정을 제거한다. | 모든 본문 문단이 선택·해석·복구 중 하나를 바꾸며, 기본 출력은 상태/다음 행동 위주이고 자세한 내용은 요청할 때만 읽는다. 짧게 하려고 필수 경고나 예외를 빼지 않는다. |

성진이 선택한 미완료 자식 처리 범위는 불완전 상태를 명확히 알리는 데까지다. 늦게 끝난 자식의 자동 회수는 이번 작업에 넣지 않는다.

## 확인된 근거

- `.claude/skills/ultra-search/SKILL.md:35–41`은 follow 종료 뒤 결과 수거를 지시하지만 `_follow.py:129–133`은 시간 초과에도 종료하고 `_watch_cmds.py:144–154`는 코드 0을 반환한다. 시간 초과를 구별하는 기존 테스트는 있으나 CLI가 재감시 명령까지 주지는 않는다.
- `_run_cmds.py:168–181`의 후속 명령은 `sys.executable`과 resolve된 소스 경로를 사용한다. 실제 출력은 `/usr/local/bin/python3 /Users/seongjin/Coding/Ultra-Search/...`였고, 현재 SKILL의 허용 패턴은 `python3 "/Users/seongjin/.claude/skills/ultra-search/..."`다. 실제 클라이언트의 권한 적용 결과는 아직 검증하지 않았다.
- `_supervisor.py:275`의 `empty`는 답변과 출처가 모두 비었는지를 뜻한다. “조사 결과 관련 사례가 없다”는 자연어 결론을 판별하지 않는다.
- 현재 사용자 설치는 저장소의 스킬 디렉터리를 가리키는 심볼릭 링크다. 같은 이름의 서로 다른 스킬 복제본은 아니다.
- 독립 검토 후 직접 확인: `_run_cmds.py:159`는 이미 계산한 runs root 대신 원래 인수를 명령 생성에 넘긴다. 기본값 생략/상대 경로 보존 때문에 호출 디렉터리가 바뀌면 다른 저장소를 보게 된다.
- 독립 검토 후 직접 확인: `_supervisor._sync()`는 기존 세션을 전체 복사하고 `_follow._drain()`은 그 전체를 읽는다. result에 쓰는 현재 턴 경계가 로그에는 적용되지 않아 resume이 과거 턴/자식 로그를 재출력한다.
- 독립 검토 후 직접 확인: `_supervisor.py:114–135`는 부모 종료 후 기본 10초까지 자식을 기다린 뒤 결과를 확정한다. orphan 자식이 나중에 끝나도 저장된 result는 갱신되지 않는다. 이는 부분 결과로 명시할 제한이지 이번에 자동 회수 기능을 새로 만들 이유는 아니다.
- 그룹의 먼저 완료된 결과는 최초 search 응답에도 들어 있다. 다음 명령이 남은 한 런으로 좁혀진다는 이유만으로 기존 결과 유실 버그라고 주장하지 않는다. 그룹 정체성 유지는 수거 단계를 자체 완결적으로 만드는 개선이다.

## 범위와 유지할 것

- 기존 search/resume → log → result 경로, 제한된 follow 시간, progress 기본 로그, 다중 스트림 커서, 원문 파일 저장, stop의 실제 과금 경고를 유지한다.
- 새 명령·상태 저장 서비스·전역 훅·광범위한 allow 규칙·검색 결과 의미를 판정하는 분류기는 만들지 않는다.
- 기존 `.claude/harness-spec.md` 삭제와 미추적 `.claude/settings.json`, `.claude/plans/`, `.codex/`는 사용자 작업으로 보존한다. 삭제된 개발 문서를 복원하거나 런타임 스킬에서 참조하지 않는다.

## 권장 실행 계약

### 1. 다음 행동을 현재 상태에서 결정한다

- `next`는 지금 실행할 행동 하나만 표현한다. 아직 발생하지 않은 완료를 가정하는 `next.then`은 제거한다.
- search/resume에 미완료 런이 있으면 감시 명령을 반환한다. log가 반환될 때 미완료 런이 남아 있으면 현재 커서를 포함한 재감시 명령을 반환하고, 대상이 모두 종료 상태면 result 명령을 반환한다.
- log의 기존 이벤트/커서 출력 뒤에 최종 JSON `{ok, command: "log", runs, cursor, next}`를 제공한다. `runs`는 각 대상의 run_id/state와 해당하는 불완전성 정보를 담는다. 커서는 기존 int/JSON 문자열 형식을 그대로 쓴다. 스냅샷 log와 follow 모두 이 요약을 반환한다.
- `next`의 필드는 `{command, bash_timeout_ms, run_in_background}`다. 감시는 기존 570초/600000ms·background=true를 유지하고 수거는 일반 Bash 제한 120000ms·background=false로 낸다. result는 수거의 끝이므로 다시 next를 만들지 않는다.
- 종료 코드 0은 로그 호출 성공이지 조사 성공이라는 의미가 아니다. 런 상태와 result가 조사 결과를 판정한다. failed/abandoned/부분 완료를 성공으로 뭉뚱그리지 않고, 그룹의 모든 감시 대상이 종료됐다는 표기도 성공한 조사와 구별한다.
- 그룹은 다음 행동에서도 그룹 정체성을 유지한다. 최종 result 명령은 전체 그룹을 수거하고, 재감시에는 부모/자식별 커서를 전달한다.
- resume의 로그 기본 범위는 이번 런의 턴이다. `_events.turn_start_index()`의 기존 마커 판정과 자식 발견 로직을 재사용해 이전 턴/이전 자식은 출력하지 않는다. 새 마커가 아직 복사되지 않았으면 과거 전체로 강등하지 말고 이번 턴을 기다린다. 원본 보존 방식은 바꾸지 않고 커서는 실제 저장 파일의 바이트 위치를 계속 가리킨다.
- `completed_with_orphans`에는 미수거 자식 ID와 “저장된 결과는 스냅샷이며 늦은 자식 결과가 자동 갱신되지 않는다”는 설명을 결과를 받는 응답에도 노출한다. abandoned에는 감시만 끝났고 실제 작업/과금이 계속될 수 있음을 노출한다. 자동 회수·세션 재연결은 만들지 않는다.
- 기존 `_next_step()`의 명령 생성과 `_follow.parse_since()` / `format_cursor()`를 공유해 최초 감시·재감시·수거가 같은 경로를 사용하게 한다. 새 범용 실행 프레임워크나 커서 형식을 만들지 않는다.
- **완료 판정:** 처음 반환된 명령과 매 응답의 다음 명령만 실행해, 시간 초과를 한 번 이상 거친 단일·그룹·정상 종료 자식 포함 런의 저장된 결과를 모두 수거하고 이미 읽은 이벤트와 resume 이전 턴을 재출력하지 않는다. orphan/abandoned는 완전한 조사 결과로 오인시키지 않는다.

### 2. 호출 경로와 권한 계약을 맞춘다

- 공개 후속 명령은 사용자가 호출한 스킬 엔트리포인트의 절대 경로를 유지한다. 심볼릭 링크를 실제 저장소 경로로 바꾸지 않는다. 내부 import 경로 해결은 그대로 둔다.
- 현재 스킬이 안내하고 허용하는 `python3 "<skill-dir>/scripts/ultra_search.py" ...` 표기를 생성한다. 인수·경로의 셸 인용은 안전하게 처리하고, 임의 코드를 실행하게 하는 문자 보간을 도입하지 않는다.
- 명령에는 `_registry.resolve_runs_dir()`가 이미 계산한 절대 runs root를 항상 전달한다. 기본값과 상대 경로 입력 모두 현재 작업 디렉터리가 바뀌어도 같은 런을 찾는다.
- 같은 생성 경로를 최초 감시·재감시·최종 수거에 사용한다. 현재 allowed-tools의 범위는 넓히지 않고 권한 문제를 광범위한 허용 규칙으로 우회하지 않는다.
- **완료 판정:** 설치 심볼릭 링크와 공백/셸 특수문자가 포함된 경로에서 반환 명령을 실제 실행할 수 있고 호출 경로가 유지된다. 기본/상대 runs dir로 시작한 뒤 디렉터리를 바꿔도 기존 런을 수거한다. 사전 승인 여부는 별도 실제 클라이언트 검증으로 판정한다.

### 3. 본문과 도움말을 실제 보장에 맞춘다

- SKILL의 수거 안내는 “알림은 감시 호출 종료이며 조사 완료 여부는 반환 상태로 판단한다; 최신 next를 따른다”로 정리한다. 필드 규격과 상세 옵션은 CLI 도움말·응답에 둔다.
- 부정적 조사 결론을 허용하는 프롬프트 원칙은 유지하되 `empty`와의 허위 연결을 제거한다. `empty`와 종료 코드 5의 설명은 산출물 부재로 한정하고 자연어 결론을 해석하지 않는다.
- progress의 목적과 상세 로그로 전환할 조건은 유지하고, 과거 출력 크기 비교·중복 옵션 설명·문서 중복을 피한다는 자기 설명은 줄인다. 고정된 성능 수치를 일반적인 보장으로 제시하지 않는다.
- search/fetch 판단 근거, stop으로 과금을 멈출 수 없다는 경고, 차단된 출처를 확보한 것으로 보지 않는 원칙은 보존한다. 본문을 줄이기 위한 새 reference 파일은 만들지 않는다.
- 수정하는 CLI 도움말은 출력에서도 의미 단위가 한 줄로 유지되게 하고 실제 `--help`로 확인한다.
- **완료 판정:** 실행 규격 변경 시 함께 바꿔야 하는 본문 설명을 줄이면서, 모델이 명령을 선택하고 결과를 해석하는 데 필요한 판단 근거를 모두 유지한다.

## 검증 seam과 순서

계획 승인 시 아래 seam의 승인도 명시적으로 요청한다. 테스트를 쓰기 전 tdd 스킬을 다시 적용하며 각 시나리오를 하나씩 red → green으로 진행한다.

1. **CLI seam:** argv → stdout/종료 코드, 반환된 후속 명령 실행 → 다음 응답. 기존 `tests/test_commands.py`의 fake Aside 바이너리를 외부 경계로 사용하고 내부 헬퍼를 mock하지 않는다. 완료·시간 초과 후 재감시·실패·abandoned·부분 완료 그룹·자식별 커서·resume 전후 턴·새 마커 지연·심볼릭 링크·공백/특수문자 경로·작업 디렉터리 변경을 검증한다. 반환 명령은 문자열 비교뿐 아니라 실제 셸 실행으로 검증하고, fixture 상태 주입은 준비 단계에만 사용하며 결과는 CLI로 관찰한다. 기대 결과는 위 계약에서 정하고 현재 출력에서 베끼지 않는다.
2. **결과 의미 seam:** 정상 종료지만 답변/출처가 없는 경우와 “관련 사례를 찾지 못했다”는 답변이 있는 경우를 구별한다. 후자는 의미상 부정적 결론일 뿐 empty가 아니다.
3. **실제 클라이언트 seam:** 격리된 테스트 환경에서 스킬을 호출해 fake Aside 기반 후속 명령을 원문 그대로 실행한다. 실제 사용하는 모델·정상 권한 모드에서 허용 패턴 적용·배경 완료 알림·다음 행동 수거를 확인한다. harness-creator의 `run_e2e.py`를 사용할 때는 permission-mode를 명시하며 skip-permissions를 사용하지 않는다. 권한 우회 모드의 통과나 subprocess 실행 성공을 이 검증의 대체로 보고하지 않는다. 실제 Aside 유료 조사는 하지 않는다. 대기/알림을 검증할 다중 턴 환경이 없으면 headless 한 번의 통과로 대체하지 말고 인터랙티브 검증 미완료로 남긴다.
4. 변경 후 `python3 -m pytest tests/test_commands.py tests/test_follow.py` 및 `python3 -m pytest tests/`로 비라이브 회귀를 확인한다. 도움말과 구조 검사도 실행한다. 테스트 임시 파일과 하네스 e2e 출력은 세션 scratchpad에 둔다.
5. `validate_harness.py`의 현재 기저 결과는 오류 2개·경고 0개이며 모두 미추적 settings의 Graphify hook 명령을 스크립트 경로로 판정한 항목이다. 현재 세션에서는 해당 훅의 안내가 실제 도착하고 바이너리도 존재하므로 스킬 결함으로 단정하거나 이번 범위에서 설정을 고치지 않는다. 변경에 따른 새 오류와 구별한다.

## 검토 결과와 남은 한계

- 독립 코드 검토 1개 완료, 변경 파일 0개·테스트 실행 없음. 감시 재개·호출 경로·runs dir·resume 로그·orphan 결과 경계를 지적했고 조정자가 관련 코드를 직접 확인했다. 검토 run: `20260916-223845-interface-audit-6324`. 이는 설계 근거이며 구현 검증 통과가 아니다.
- 확인한 기저 검증은 실제 help 출력과 구조 검사다. 회귀 테스트·실제 브라우저 실행·정상 권한 매칭·모델의 next 준수는 아직 실행하지 않았다. 구현 뒤 해당 환경에서 확인하지 못하면 미검증으로 남긴다.
- orphan 자동 회수는 성진의 결정으로 범위 밖이다. 자식 결과가 필수인 실제 작업에서 현재 부분 결과가 부족해지면 성진과 별도 설계를 연다. 이번에는 인터페이스가 이 제한을 숨기지 않는 것으로 완료를 판단한다.
- 런타임 본문은 문단별로 유지/축약/CLI로 이동/삭제를 판정하고 위 네 기준으로 마지막 검토를 한다. 과거 이력·개발 문서·별도 새 reference를 읽어야 사용할 수 있는 스킬로 만들지 않는다.
- 테스트 seam과 구현 승인은 이 계획의 최종 승인에서 받는다. 승인이 나면 파일 변경 3단계의 트래커를 열고 각 완료 판정 기준을 그대로 기록한다.
